## Architecture findings

| Area / inspected files | Relevant behavior and consequence |
| --- | --- |
| `src/main.js` | `boot()` owns wiring and guards duplicate initialization with `INSTANCE_KEY`. Creates game/session routing, effects, renderer, controls, modal controllers and one `createLoop()`. Its returned `stop()` detaches the loop, input, UI and sizing resources. Ambient ownership belongs here |
| `src/core/timing.js` | `createLoop()` uses requestAnimationFrame; start is idempotent, stop cancels its handle. `frameDelta()` caps at `CONFIG.timing.maxFrameSeconds` (0.04 s). Reuse that delta without altering the loop or simulation stepping |
| `src/core/game.js`, `state.js`, `random.js`, `checkpoint.js`, `sessions.js` | Simulation is plain data with events, private seeded streams, checkpoints and an active-game facade for pot/practice switching. Ambient state must stay outside all of these structures |
| `src/rendering/renderer.js` | `createRenderer().draw()` maps logical 920 × 790 coordinates to backing pixels, clears each frame, and advances a private visual clock. Daily Pour, Biscuit Breakout, Crossing the Street, crossing previews and Tea Run return early. Normal cup rendering uses a saved camera transform, a 1.16× Compact camera during active cup scenes, and optional shake; overlays draw after restore |
| `src/rendering/effects.js`, `tea.js` | `createEffects({ random })` demonstrates injected cosmetic randomness; `createTea()` polls `prefers-reduced-motion` during update. Effects have mixed pause policies; some decay while paused. They are not a single reliable clock for a colony or its reading delay |
| `src/rendering/strange.js` | Separate presentation controller, `handle/update/shown`, blocked-screen handling and reduced-motion policy are useful patterns. Rewind explicitly holds simulation/effects and renders recorded state. Its recording, schedule and `game.noteStrange()` integration are specific to Mushroom Tea and must not be copied into ambient behavior |
| `src/rendering/canvas.js`, `src/ui/viewport.js` | `attachCanvasScaling()` sizes the game backing store from its displayed rectangle, caps DPR at 2, observes resize and returns cleanup. `attachViewportFit()` budgets Full View height using header/main geometry, window resize and visualViewport resize |
| `src/config.js`, `gameplay/arena.js`, `rendering/porcelain.js` | Cup center is (451, 400), liquid radius 273, but porcelain rings, handle, spoon, beams and effects extend farther. An exclusion based only on liquid radius is unsafe. Avoid coupling ants to cup paths or gameplay collision code |
| `styles/main.css`, `index.html` | `.playfield` clips overflow; `.stage` is positioned and uses size containers/grid. HUD, rail, action dock and reading panel change available space. Later rules hide the Full View sidebar. The 190 px control rail disappears when controls hide. Generic `canvas` and Compact canvas selectors would also affect an added canvas unless explicitly overridden |
| `src/ui/hud.js` | `hudText()`, `offerCards()` and `createHud().update()` own text and offers. `readingReadyAt()` gates the final DOM explanation and buttons. The final reading is not a canvas label: `#readingPresentation` includes a focusable, scrollable `.reading-copy`, fortune/effect/observations and upgrade choices |
| `src/ui/presentation.js`, `collection.js`, `instructionOverlay.js`, `titleScreen.js` | Native dialogs own focus and blocked state. Tea Break reparents existing panels; closing restores focus and conditionally resumes. Title → instructions → game requires fresh activation; held keys are settled at boundaries. Ambient rendering must not add input listeners or change these transitions |
| `src/input/controls.js`, `onScreenControls.js`, `input/settings.js` | Blur/hidden releases input and pauses eligible scenes. Visibility preference changes inert controls, captures and menu location. A reading cannot be paused through `game.pause()`, so ambient blur/visibility gating must also work independently of the game phase |
| `src/rendering/splashArt.js`, `ui/titleScreen.js`, title markup/CSS | Current illustration is a deterministic 256 × 160, 16-colour pixel canvas painted once after loop start. `#arcadeSplash` is a native modal in the top layer; a stage canvas cannot decorate over it. Title button, loading status and subtitle are separate DOM elements |
| `package.json`, `vite.config.js`, `playwright.config.js`, `.github/scripts/ci-changes.js` | Vitest runs Node unit tests; Playwright runs production output beneath `/Steeped-in-Trouble/` in desktop Chromium/Firefox and mobile Chromium. Markdown here qualifies for documentation-only CI. Runtime work will run the existing checks |

Current frame order is effects → controls → event drain → conditionally
`game.update()` → event drain → Strange Happenings → audio → renderer → HUD →
presentation → collection. `blocked` includes title, instructions, Tea Break
and collection; the loop keeps rendering behind them. Paused simulation
does not imply all presentation clocks stop. Do not insert colony stepping
inside `game.update()`, `effects.update()`, or a renderer branch that can
return before drawing it.

Graphics quality is initialized from `?graphics=high|low`, then stored
`steeped-in-trouble:graphics`, then High. The settings button changes
`renderer.quality` and persists it. Low reduces existing renderer detail;
it is not currently a global animation switch. Share this existing setting,
without introducing another preference or save field.

## Rendering options and recommendation

| Option | Benefits | Costs / limitations |
| --- | --- | --- |
| A: Canvas-only ants | Matches existing vector painters; one bounded draw pass, one RNG policy, no per-ant elements, simple snapshots and complete visual/input isolation | Needs explicit geometry, clipping, DPR and lifecycle handling; an existing game-canvas pass cannot cover gutters outside its bounds |
| B: HTML/CSS ants | Easy positioning and transform animation; a text gag could use a visual duplicate | Multiple legs, carriers and synchronized groups add elements/animation cancellation; autonomous irregular paths still need JS. Modal layering, focusable descendants and duplicate text demand care; less consistent with current painters |
| C: Canvas gameplay plus DOM/CSS title ants | Can suit a separately authored title illustration | Two ant rendering paths and motion policies for little benefit; cross-screen cleanup and deterministic screenshots become harder |

**Recommend A: a transparent, decorative Canvas 2D layer inside `.stage`,
stepped by the existing loop.** Protect the entire displayed `#game`
rectangle initially, plus every UI exclusion. Use the existing empty stage
gutters instead of introducing cup-outline geometry or shrinking gameplay.
This avoids the renderer's early returns, camera/shake transforms and
adventure-specific art bounds. It is a second drawing surface, not a second
animation loop. No animation library or runtime dependency is warranted.

Later title decoration can use the same ant painter on a title-local canvas
inside the native modal, clipped to the illustration region. A static title
illustration plus Canvas ants is still one ant rendering approach. Do not
try to raise the stage layer above a modal with a large z-index. If title
art is raster or SVG, it can remain a static artwork asset behind that layer.

## Component boundaries and insertion points

Keep two small modules initially; proposed names/API are guidance, not new
framework contracts:

- `src/rendering/ambient.js`: owns a private colony clock, RNG, bounded ant
  and prop arrays, behavior transitions, and Canvas painting. Accepts safe
  regions and presentation policy as data. No DOM, game commands, storage,
  event-drain ownership, game-engine imports or global timers; the pure RNG
  utility is reusable. Export a reusable ant painter here if the title needs
  it; split only if it grows.
- `src/ui/ambient.js`: attaches the decorative surface, measures available
  geometry, supplies quality/motion/screen policy and disposes observers
  and listeners. Use the existing UI factory/`dispose()` convention. The
  adapter can live together with the controller during the first increment
  if that is clearer, while keeping geometry/policy functions testable.
- `src/main.js`: creates the adapter once, calls its frame/update method
  **after** `hud.update()`, `presentation.update()` and `collectionUI.update()`
  so phase-driven layout has been applied, and disposes it from `stop()`.
  Pass current game phase, modal blockers, rewind hold and renderer quality
  as read-only values. Do not change existing `dt`, `blocked`, `shown`,
  event ordering or commands to accommodate ants.
- `index.html`, `styles/main.css`: one `aria-hidden="true"`, nonfocusable
  ambient canvas in `.stage`, absolute and out of grid flow, clipped to the
  host, `pointer-events: none`. Use a specific canvas selector to override
  generic width/height/aspect-ratio rules. Keep it below UI/focus indicators.
  A future title surface uses an equally specific selector.

Use CSS pixels as ambient coordinates; size its backing store from the host
rectangle at DPR capped to 2, using the pattern in `attachCanvasScaling()`.
Do not call that helper unchanged: it measures the canvas and assumes CSS
provides its sizing; the new absolute host surface needs explicit sizing.
Reallocate backing pixels only when dimensions/DPR change. Cap area/detail
if profiling shows the transparent surface is too expensive; no full-screen
filters, shadows, pixel reads or per-frame static-art rebuilding.

### Safe space and population

Measure stage-local rectangles only when dirty. Start with the stage's
visible inner bounds intersected with viewport/playfield clipping. Subtract
the displayed game rectangle and visible overlapping panels/offers/controls,
including reading, acknowledgment and focus clearance. Inflate exclusions
by an initial 8 CSS px clearance, then account for complete ant/cargo size
when eroding safe regions below. Never rely on paint order alone.

Represent the remaining space as a few rectangles/corridors. Erode them by
the complete animated footprint (legs and rotating cargo included); count
capacity using both usable area and a minimum corridor width/length. Fill
up to the minimum of that capacity and a display-space budget: provisionally
6–12 in generous regions, 3–6 in moderate regions, 0–2 or zero in cramped
regions, with an absolute cap of 12. Disconnected slivers do not combine
into a route. Teams consume the same ant budget and need a wider corridor.
Short landscape layouts may use few ants even with broad side gutters.

Use measured safe-region capacity, not window-width breakpoints. In the
first increment, ordinary ants need at least a practical 32 CSS px corridor;
confirm that minimum and their rendered size by visual review. The preliminary
population ranges are ceilings/guidance, not requirements to fill every scene.
Zero is correct when there is no readable, safe route or entry/exit portal.
Do not expand the host, move controls or reduce the game to meet a target.

Invalidate on stage/game/reading/offer size changes, viewport/visualViewport
resize, DPR changes and view/phase/reading-ready/control-visibility changes.
Observe relevant elements and compare a small layout-policy key in the
existing frame. Explicitly invalidate when an offer appears or UI reparents;
ResizeObserver alone misses same-size position changes. Recompute at most
once after a dirty layout settles, with reads before backing-store writes.
Do not scan all document elements or read layout per ant/per frame. Scroll
that changes clipping also invalidates visibility; measure only the active
host. Geometry changes cancel a gag and retire/reposition ants before the
next draw, so paths never continue through a newly visible panel.

### Behavior and cost

Start with enter → wander → leave → dormant. Pick short, smooth path segments
at infrequent decision points with a private RNG; interpolate headings to
avoid jitter. Entry/exit is through a real visible-host edge with safe
access, with clipped offscreen endpoints. No teleporting into the center.
Use a quiet cooldown and cohort lifetime so the scene is sometimes empty.

Add following by assigning one leader and a delayed path/offset to a few
followers, rather than simulating pheromones or pairwise forces. Crumbs are
private decorative props: approach → attach → carry to exit. Sugar-cube
teams share one cargo path and fixed relative offsets; a short synchronized
lift is enough to sell cooperation. Crumbs/cubes are never entities in the
game and cannot be collected, shot, collided with or scored.

Bound the population and prop count (initially one cargo job at a time).
Reuse objects/segment buffers; no map/filter chains, text measurement,
sorting, image creation or geometry search in the draw path. Behavior
decisions can run at about 10 Hz with interpolation each frame. After a slow
frame, discard excess decorative decision time instead of running an
unbounded catch-up loop. Replan only at decisions or geometry changes.
Optional gameplay reactions can later consume selected existing events in
`handleEvents()` after their ordinary processing, with no additional drain,
no commands back to the game and a cooldown to avoid per-kill churn.

### Lifecycle, quality and motion policy

| Situation | Proposed colony behavior |
| --- | --- |
| Normal active cup | Animate in safe gutters; simulation and rewind state stay untouched |
| Reading ceremony | Perimeter ants may continue safely; no text joke before final reading and additional visible dwell |
| Final reading, no offer | Perimeter behavior; optional bounded flavor-text gag under rules below |
| Upgrade, shortage, arcade or Day decision; adventure/boss intro/outro | No gag. Initial scope suppresses the colony during these decision/intro/outro screens |
| Active boss/adventure | Initial scope suppresses it. Later opt-in can use stage gutters without altering scene painters |
| Paused, blur, hidden, Tea Break, collection, instructions, rewind hold | Freeze colony time and behavior; cancel/restore text immediately. Hide/clear under blocked screens; hidden surfaces do no drawing or catch-up |
| Game over | Clear jobs and text; keep off during cup shatter/result presentation |
| Title | Later separate title host, active only when title is ready/open, visible and focused; no game-stage colony behind it |
| Screen/pot/practice replacement, restart, disposal | Clear previous jobs and gags; reset screen identity/cooldown as needed. No old target or RNG object retained in saves |
| High | Full permitted population, following, crumb and cooperative jobs; simple leg animation |
| Low | At most 2 ants if geometry permits; basic enter/wander/leave only, no teams/text gag/extra effects; inexpensive simple bodies |
| Reduced motion (including a live preference change) | No moving colony or gag; clear/restore immediately. The title may retain a still ant/sugar illustration |

Read the media query directly in the adapter, including its change event.
Reusing `effects.fx.tea.reduced` alone can lag while effects are held by
rewind. Keep visibility/focus policy independent of `game.pause()`, since
non-playing screens still need it. Cleanup removes all observers, media and
window/document listeners, surfaces and temporary presentation state; no new
requestAnimationFrame, interval, timeout or unresolved animation promise.

### Inter-round text mischief

**Recommended target: a short, purely decorative caption drawn in a safe
reading gutter by the ambient painter**, e.g. “A very official tea inspection.”
Ants carry that displayed line away and bring it back. This keeps the joke
entirely in presentation and avoids hiding the actual fortune, instructions,
score or choices. It also keeps all ant/text animation on Canvas. Caption
wording is a review choice; it conveys no information needed to play.

Do not target `#readingTitle`, `#compactFortune`, `#compactEffect`, observations,
secrets/rewards, offer headings/cards, action buttons, `#readingAnnouncement`,
or any accessible label/live region. The canonical DOM reading, layout,
scroll position, accessible text and focus order remain untouched. If the
owner wants an existing DOM line carried instead, that is a separate design
decision requiring an opt-in visual copy and complete cancellation rules;
do not transform a live panel or use `innerHTML` snapshots.

Proposed sequence, entirely driven by colony visible time:

1. Require `phase === 'reading'`, no upgrade offer, final
   `readingTime >= readingReadyAt(state)`, High, motion allowed, focused and
   visible, no modal/rewind, a fitting caption and a safe exit route.
2. Show the caption stationary, then accumulate **at least 8 seconds after
   the final reading becomes ready and visible** before sampling a rare
   opportunity. Ordinary readiness is 2.7 s; The Leaves Lie is 4.1 s.
   Readiness is only a lower bound, not proof a person has finished reading.
   Hidden/blurred time never counts; reset dwell when content/geometry changes.
3. Skip while the pointer is in the reading panel or keyboard focus is in
   reading copy/any choice/control. Any such engagement during a gag cancels
   it immediately. Never delay Enter, enablement or progression for ants.
4. One opportunity per completed-cup screen, e.g. a private 20% chance after
   dwell. A small team carries the caption out (up to 2 s), stays away at
   most 1.5 s, returns within 2 s, then leaves it still. Restore by 5.5 s
   from pickup. Skip if a route/group footprint cannot fit.
5. Any phase/session change, focus/visibility loss, blocker, resize, setting
   change, target invalidation or stop restores the caption to its stationary
   position or removes that screen's decorative caption immediately. No
   delayed callback can affect the next reading. If the player stays, the
   text returns without requiring a key, click or next round.

This supplies the requested visual joke without making the player wait or
turning essential UI into moving artwork. New caption placement must not
take space from the reading or controls. A constrained viewport simply skips
it. Keep the caption below 20 words and fit it once on layout change, never
per frame. Screen readers do not need announcements for decorative antics.

## Risks and decisions for review

- **Surface cost and CSS:** the new stage canvas can be much wider than the
  game canvas. Cap DPR, avoid offscreen painting and scope selectors so it
  cannot change grid tracks, touch behavior or existing canvas sizing.
- **Stale geometry:** reading-ready splits, reparented offers and hidden
  controls change space without a window resize. Use dirty geometry and
  clear jobs before rendering against a changed layout.
- **Text safety:** readiness alone does not establish reading completion.
  Prefer the dedicated flavor caption, long visible dwell and engagement
  cancellation. Whether the owner instead wants an existing decorative DOM
  line is unresolved; essential text remains ineligible in either design.
- **Determinism:** never share game, effects or Strange Happenings RNG
  objects. Instantiate an ambient-only generator with `createRandom()` or
  inject a random function; private deterministic seed for tests only. Do
  not export its cursor to checkpoints or call gameplay from reactions.
- **Motion and pauses:** polling only phase or existing renderer time would
  animate behind blocked/hidden screens. Use the explicit policy table and
  cancellation on live quality/motion changes.
- **Presentation taste:** ant size, speed, population capacity, caption copy
  and 20% opportunity rate need owner visual review. The geometry examples
  demonstrate space, not that the chosen population looks good.
- **Performance:** no colony exists yet, so there is no measured feature
  cost or device qualification. Use local browser profiling once built;
  short/mid-size layouts and Low should retain little or no ambient work.

## Acceptance criteria for the complete Ant Colony

1. All five ordinary behaviors can be observed with a controlled cosmetic
   seed: irregular smooth wandering, following, crumb pickup/carry, multiple
   carriers sharing an oversized sugar cube, and quiet enter/leave cycles.
2. Total ants never exceed 12; capacity responds to actual safe geometry.
   Medium/cramped layouts reduce or eliminate visitors; complete ants and
   cargo never intersect protected game/UI rectangles. Controls remain at
   least 44 × 44 CSS px, visible, focusable and unobscured.
3. Resize, orientation, Full/Compact switch, reading reveal and control
   visibility changes retire/replan safely before the next draw without
   moving or resizing gameplay to make room.
4. Identical scripted games with ambient off/on and different ambient seeds,
   graphics/motion policies and ambient update counts produce identical
   gameplay state, event sequence, RNG exports and checkpoint bytes at the
   same simulation steps. Ambient contains no gameplay entity or save field.
5. No new game command, global input shortcut or pointer capture is added.
   Existing title/instruction/Tea Break/collection controls and held-input
   isolation work through every animation state.
6. Pause, hidden/blur, blockers and rewind stop colony progression; screen
   changes clear old jobs. Resume has no catch-up burst. Disposal removes
   listeners/observers and leaves no animation or temporary text state.
7. High and Low obey their stated policies immediately. Reduced motion has
   no moving ants, text theft, steam or cape movement, including live changes.
8. The approved flavor text remains still through final reveal plus at least
   8 visible seconds, never runs during offers/decisions, returns within its
   5.5-second bound, and cancels immediately on engagement/context changes.
   Essential DOM text, accessible names/live regions, scroll and focus remain
   unchanged; continued waiting never requires an action to restore text.
9. Bounded population/props and cached geometry prevent per-ant layout or
   growing arrays. On the same machine/browser at 800 × 600 and 844 × 390,
   compare identical seeded/clocked runs with ambient off/on; provisionally
   target under 1 ms p95 added ambient update/draw CPU time in High. Record
   actual results and machine; no claim of universal hardware performance.
   In Low/reduced/hidden/no-space states, profiling shows the expected zero
   or minimal work. A short sustained run shows no accumulating jobs/listeners.
10. Existing tests remain intact and green; focused new tests cover these
    contracts. Complete browser regression is required for the eventual
    substantial rendering change, and existing Windows/Ubuntu release
    qualification remains required before a future versioned release.
